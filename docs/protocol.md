# 로봇 통신 프로토콜 v1

웹(노트북)과 AIHand(micro:bit, MakeCode 펌웨어)는 USB 시리얼(Web Serial)로 **텍스트 한 줄씩** 주고받는다.

- 한 줄 = 명령 하나, 끝은 `\n`
- 글자는 영어 대문자·숫자·`_`·쉼표만 사용
- 값이 있으면 `명령,값` 처럼 쉼표로 붙인다 (공백 없음)
- 구현: 웹 `src/core/robot/protocol.js`·`serial.js`, 로봇 `firmware/main.ts` (펌웨어 F3. F1 로봇 명령 + F2 WonderCam 태그 인식 + F3 숫자 인식)
- **이 문서, `protocol.js`, `firmware/`는 항상 같이 고친다.**

## 웹 → 로봇

| 명령 | 뜻 | 로봇 응답 | 검증 |
|---|---|---|---|
| `HELLO` | 인사 동작: 손바닥 편 채 손목 흔들기 → REST | `DONE,HELLO` | 확인됨 (F1, 2026-11-09) |
| `POSE,<이름>` | 손모양 만들기. 이름은 `src/data/poses.json`의 `name` (예: `POSE,ROCK`) | `DONE,POSE` | 확인됨 (F1, 7종, 2026-11-09) |
| `REACT,OK` | 칭찬 반응: 주먹 ↔ 반쯤 쥔 자세 2번 | `DONE,REACT` | 확인됨 (F1, 2026-11-09) |
| `REACT,RETRY` | "다시 해 볼까요" 반응: 새끼→검지 물결 → REST | `DONE,REACT` | 확인됨 (F1, 2026-11-09) |
| `REST` | 쉬는 자세: 손가락·손목 모두 90° | `DONE,REST` | 확인됨 (F1, 2026-11-09) |
| `SPEED,SLOW` / `SPEED,NORMAL` | 모든 이동·대기 시간 ×2 / ×1 | `DONE,SPEED` | 확인됨 (F1, POSE·반응 동작 모두, 2026-11-09) |
| `PING` | 연결 확인 | `PONG` | 확인됨 (F1, 2026-11-09) |
| `CAM,TAG` | WonderCam을 태그(AprilTag) 인식 모드로 바꾼다 (색 카드, STEP 3) | `DONE,CAM` / 카메라 없음 `ERR,NO_CAM` / 모드가 안 바뀜 `ERR,CAM_MODE` | 미확인 (F2) |
| `CAM,NUM` | WonderCam을 숫자 인식 모드로 바꾼다 (숫자 카드 1~5, STEP 1) | `CAM,TAG`와 같음 | 미확인 (F3) |

- 웹은 `CAM` 명령을 직접 부르지 않는다. `core/card`가 프로그램의 구독(`onCard` / `onNumber`)에 맞춰 알아서 보낸다 (아래 "카메라 모드").
- 카메라 모드가 실패(`ERR,NO_CAM`, `ERR,CAM_MODE`)하면 펌웨어는 모드 없음이 되어 `TAG`·`NUM` 줄을 보내지 않는다.
- 펌웨어 F2에 `CAM,NUM`을 보내면 `ERR,BAD_ARG`이고 태그 모드는 그대로다. 웹은 "숫자 카드는 펌웨어 F3가 필요해요"로 안내하고 숫자는 Mock으로 받는다.
- 펌웨어 F1에 `CAM`을 보내면 `ERR,UNKNOWN_CMD`. 웹은 "펌웨어 F3가 필요해요"로 안내한다.

동작 각도·시간은 `docs/hardware-check.md` 3번·부록 5, 명령별 동작 시간은 `firmware/README.md`.

## 로봇 → 웹

| 줄 | 뜻 |
|---|---|
| `DONE,<명령>` | 명령 동작을 마침. `<명령>`은 받은 명령의 이름 부분 (`POSE,ROCK` → `DONE,POSE`) |
| `TAG,<번호>` | WonderCam에 보이는 태그(AprilTag tag36h11) 번호. **바뀔 때만 한 번** 보낸다. 웹의 `core/card`가 `tags.json`으로 색(`0` 빨강, `1` 파랑, `2` 노랑, `3` 초록, `docs/cards.md` 3-A)으로 바꿔 `ctx.card.onCard({ color })`로 넘긴다. 미확인 (F2) |
| `TAG,NONE` | 보이던 태그가 **0.5초 넘게** 안 보임 (카드를 치움). 웹은 `onCard`를 부르지 않고 "지금 보이는 카드"만 비운다. 미확인 (F2) |
| `NUM,<1~5>` | WonderCam에 보이는 숫자 카드. 태그와 같은 규칙으로 **바뀔 때만 한 번**. 웹은 `ctx.card.onNumber({ number })`로 넘긴다. 미확인 (F3) |
| `NUM,NONE` | 보이던 숫자가 **0.5초 넘게** 안 보임. 미확인 (F3) |
| `RAW,NUM,<숫자>,<확신도×100>` | 펌웨어 `DEBUG_NUM = true`일 때만. 확신도 기준값을 정하려고 실물에서 재는 줄. **웹은 무시한다** (`UNKNOWN`) |
| `PONG` | `PING` 응답 |
| `ERR,<내용>` | 오류. `ERR,UNKNOWN_CMD` (모르는 명령), `ERR,UNKNOWN_POSE` (모르는 손모양), `ERR,BAD_ARG` (값이 틀림). 오류가 나면 로봇은 움직이지 않는다 |

## 동작 규칙

- 웹은 명령을 **하나씩** 보낸다. 앞 명령의 `DONE`을 받은 뒤 다음 명령을 보낸다.
  (Mock도 같은 규칙으로 명령을 줄 세워 처리한다.)
- `ctx.robot.*` 함수는 `DONE`을 받으면 resolve 되는 Promise를 돌려준다.
- 통신 속도(baud rate): **115200**
- `DONE`은 정해진 시간이 지나면 보낸다. 서보가 실제로 도착했다는 뜻이 아니다.
- 로봇은 동작하는 동안 웹이 보낸 글자를 받지 못한다 (서보 명령 때 시리얼 통로를 확장보드로 돌리기 때문). 동작 중에 보낸 `PING`은 사라진다 (F1 실물 확인, 2026-11-09).

### 카드 인식 줄 (`TAG`·`NUM`, 펌웨어 F2·F3)

- 카메라는 한 번에 한 모드만 쓴다. 태그 모드면 `TAG` 줄만, 숫자 모드면 `NUM` 줄만 보낸다.
- 펌웨어는 켜질 때 모드를 바꾸지 않는다 (반복문에 늦게 들어가 `PING`에 못 답하지 않게). `TAG`·`NUM` 줄은 `CAM` 명령이 성공한 뒤부터 나온다.
- 명령을 처리하지 않을 때 약 0.1초마다 WonderCam 결과를 읽는다 (I2C). 명령 처리와 카메라 읽기는 펌웨어의 반복 하나에서 차례로 하므로, 서보가 움직이는 동안(시리얼 통로가 확장보드 쪽)에는 카메라 줄을 보내지 않는다.
- 그래서 로봇 동작 중에 보여준 카드는 동작이 끝난 뒤에도 보이고 있으면 그때 알린다. 동작 중에 보여줬다 바로 치운 카드는 알리지 못한다.
- 같은 카드를 계속 들고 있으면 다시 보내지 않는다. 다시 답하려면 카드를 내렸다가(0.5초 넘게) 다시 보여준다.
- 태그가 여러 개 보이면 하나만 보낸다: 이미 알린 태그가 아직 보이면 그것, 아니면 가장 작은 번호.
- 인식이 0.17~0.34초씩 끊기는 문제(`hardware-check.md` 4번) 때문에 사라짐은 0.5초 기다린다. 값은 종이 카드 테스트 후 조정 [검증 필요]
- `CAM` 명령으로 모드를 바꾸면 보이던 카드는 없는 것으로 치고 처음부터 다시 알린다. 웹도 `DONE,CAM`을 받으면 같은 규칙.
- 태그와 숫자는 같은 규칙(펌웨어의 `report()` 함수 하나)으로 보낸다: 바뀔 때만 한 번, 0.5초 넘게 안 보이면 `NONE`.
- 숫자 인식은 항상 가장 확신하는 숫자를 준다. 카드가 없으면 숫자 `0`이다. 그래서 숫자가 1~5가 아니거나 확신도가 `MIN_CONF`(80%)보다 낮으면 안 보인 것으로 친다. 교구 숫자 카드는 10~15cm에서 읽힌다 (2026-11-11 실물 측정, `hardware-check.md` 부록 8)
- `TAG`·`NUM` 줄은 명령 응답이 아니다. 명령의 `DONE`을 기다리는 중에 와도 된다 (웹 `serial.js`는 기다리는 명령과 상관없이 `core/card`로 넘긴다).

### 시간 초과와 재동기화 (`serial.js`)

명령별 시간 초과 = SLOW 기준 동작 시간 + 여유.

| 명령 | 시간 초과 | 동작 시간 (NORMAL / SLOW) |
|---|---|---|
| `PING`, `SPEED` | 1.5초 | 바로 |
| `POSE`, `REST` | 3초 | 약 0.65초 / 1.25초 |
| `REACT` | 10초 | OK 약 2.1초 / 4.1초, RETRY 약 3.5초 / 6.7초 |
| `HELLO` | 10초 | 약 3.0초 / 5.8초 |
| `CAM` | 6초 | 보통 0.1~0.2초. 최악 약 5.1초 = 카메라 다시 찾기 약 1초 + 모드 전환 약 4.1초 (공식 ChangeFunc: 0.1초 + 0.05초 × 80) |

- 시간 초과나 `ERR`가 나도 `ctx.robot.*`는 reject 하지 않고 `{ type: 'ERR', message }`로 resolve 한다. 상태 표시줄에 알리고 활동은 계속한다. 잘못된 손모양 이름만 바로 에러를 낸다 (프로그램 코드 실수).
- 시간 초과 뒤에는 다음 명령 전에 `PING`을 보내 `PONG`을 받을 때까지 기다린다 (최대 3번). 그 사이 늦게 온 `DONE`은 버린다. 3번 모두 `PONG`이 없으면 연결이 끊긴 것으로 본다.
- 연결이 끊기면(USB 빠짐, 응답 없음) 로봇만 Mock(화면 속 로봇손)으로 돌아간다. 다시 연결하려면 상태 표시줄의 "AIHand 연결" 버튼을 누른다.
- 웹 쪽에서 만드는 오류 `message`: `TIMEOUT`, `NO_RESPONSE`, `DISCONNECTED`, `NOT_CONNECTED` (로봇이 보내는 줄이 아님)
- `TAG`·`NUM`·알 수 없는 줄(확장보드 잡음, `RAW` 측정 줄 등)은 기다리는 명령에 영향을 주지 않는다. `TAG`는 `onTag`, `NUM`은 `onNumber`로 `core/card`에 넘긴다.

### 카메라 모드 (`core/card`)

- 프로그램이 `ctx.card.onCard`를 새로 구독하면 태그 모드, `ctx.card.onNumber`를 새로 구독하면 숫자 모드를 원하는 것으로 본다 (가장 최근 구독 기준).
- 구독을 해제할 때는 모드를 바꾸지 않는다. STEP 3처럼 문제마다 구독·해제를 되풀이해도 `CAM,TAG`는 처음 한 번만 간다.
- 원하는 모드와 카메라 모드가 다르면 `CAM,TAG` / `CAM,NUM`을 보낸다. 로봇 명령과 같은 줄(큐)을 쓰므로 로봇 동작이 끝난 뒤에 간다. 바꾸는 동안(최대 약 5초) 개발자 입력 영역에 "WonderCam: 모드 바꾸는 중"을 보여 준다.
- 프로그램은 구독한 바로 뒤 `await ctx.card.ready()`로 바꾸기가 끝날 때까지 기다릴 수 있다. 실제 카메라가 그 모드로 준비됐으면 `true`, Mock 입력만 되면 `false`.
- 실패하면 같은 연결에서는 그 모드를 다시 시도하지 않는다 (문제마다 5초씩 막히지 않게). AIHand를 다시 연결하면 처음부터 다시 맞춘다.
- 실제 카메라가 연결돼도 개발자 입력의 Mock 버튼·키보드(색 R/B/Y/G, 숫자 1~5)는 계속 동작한다.

### 연결 순서

1. 상태 표시줄 "AIHand 연결" 클릭 → Chrome 포트 고르기 창에서 micro:bit 선택
2. 115200으로 열고 `PING` → `PONG` 확인 (최대 3번)
3. `core/card`가 지금 원하는 모드(처음에는 태그, 숫자 화면이 열려 있으면 숫자)로 `CAM,TAG` / `CAM,NUM` 전송 → `DONE,CAM`이면 카드 입력이 실제 WonderCam으로 바뀐다. `ERR`면 카드만 Mock(키보드·버튼)으로 남고 로봇은 실제로 쓴다
4. 홈의 진행 속도로 `SPEED,SLOW|NORMAL` 전송. 홈에서 속도를 바꿀 때도 다시 보낸다
5. `REST` 전송 (쉬는 자세). AIHand 서보는 켜진 뒤 **첫 명령을 정한 속도와 상관없이 최고 속도로** 움직인다 (2026-11-13 실물 확인). 그 빠른 첫 움직임을 활동 중이 아니라 연결할 때 끝내려고 보낸다
6. 연결이 끊기면 로봇·카드 모두 Mock으로 돌아간다. 다시 연결하면 2~5를 다시 한다

## Mock 모드

`src/core/robot/mock.js`는 실제로 보내지 않고, `protocol.js`로 같은 문자열을 만들어 화면에 "보낸 명령"으로 보여준 뒤 0.8초 뒤 `DONE`을 받은 것처럼 처리한다.

카드 Mock: `src/core/card/mock.js`. 개발자 입력의 색 버튼이나 키보드 R/B/Y/G로 `onCard({ color })`, 숫자 버튼이나 키보드 1~5로 `onNumber({ number })`를 낸다. 실제 WonderCam이 연결되어 있어도 이 입력은 계속 동작한다 (카드가 안 읽힐 때 대신 입력).
