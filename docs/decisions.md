# 결정 사항

2026-11-13까지 팀이 확정한 내용. 새로 정하거나 바꾸면 날짜와 함께 이 문서를 고친다.
자세한 근거·측정 결과는 각 항목의 "관련 문서"를 본다.

## 1. 시연 형태

- 로봇손 앞에 두는 **전용 스테이션**으로 시연한다.
  - 라즈베리파이 5 + Touch Display 2 (7인치, 보드는 디스플레이 뒷면에 붙임) + Active Cooler
  - 웹캠: 로지텍 C270
  - USB 스피커폰: 자브라 스피크 510
- 전원을 켜면 Chromium **키오스크 모드**로 앱이 전체 화면으로 자동 실행된다.
  - 시크릿 모드(`--incognito`)는 쓰지 않는다. 활동 기록을 유지하기 위해서다.
- 스테이션은 **인터넷 없이** 동작한다.
  - 앱은 라즈베리파이 로컬에서 실행한다.
  - MediaPipe wasm·모델과 글꼴도 로컬에 둔다.
  - 시연 때는 **휴대폰 핫스팟(아이폰)을 켜 둔다** (2026-11-13). 라즈베리파이에 RTC 배터리가 없어 켤 때 인터넷으로 시계를 맞춰야 하고, 보호자 앱 요약도 바로 보내기 위해서다. 핫스팟이 끊겨도 앱은 그대로 동작한다.
- 난이도와 설정은 대시보드에서 조정한다.

관련 문서: `README.md` "라즈베리파이 준비", `docs/hardware-check.md` 5번 (라즈베리파이 FPS·GPU 측정)

## 2. 미션맵 배치

- AIHand는 세워서 두고, 웹캠은 로봇 받침대 바로 앞에 둔다.
- 손 인식과 카드 보여 주는 자리는 **로봇 앞 같은 위치 한곳**이다. 웹캠과 WonderCam이 같은 자리를 본다.
- 숫자 카드는 **WonderCam 숫자 인식 모드**로 읽는다 (AprilTag 태그 방식이 아니다).
- 색깔 카드(STEP 3)는 AprilTag 태그 모드(펌웨어 F2)로 읽는다. 임시 결정이며 종이 카드로 확인한 뒤 확정한다 (#17).

관련 문서: `docs/hardware-check.md` 4번·부록 8 (숫자 인식 확신도·거리)

## 3. 시연 코스

- 순서: **손운동(STEP 4) → 가위바위보(STEP 2) → 숫자 기억(STEP 1) → 색깔손(STEP 3)**
  - 이유: 손으로 하는 활동 → 카드로 하는 활동 (입력 방식이 한 번만 바뀐다), 쉬운 것 → 어려운 것
- STEP 번호와 폴더명(`step1-memory` 등)은 바꾸지 않는다. 화면에는 코스 순서("1번째 활동")로 보여 준다.
- 시너지 설명
  - 순서 자체의 이유 (위)
  - 활동마다 다른 역할

    | 활동 | 역할 |
    |---|---|
    | 손운동 | 모방·움직임 |
    | 가위바위보 | 조건 판단 |
    | 숫자 기억 | 순서 기억 |
    | 색깔손 | 주의 전환 |
- **보류** (지금 범위에서 뺌)
  - 손모양 이어지기 (앞 활동의 손모양이 뒤 활동에 다시 나오기)
  - 오늘의 손모양 회상 (코스 처음에 보고 끝에 떠올리기)
  - 앞 결과로 다음 활동 맞춤 조정

## 4. 기록과 보호자 앱

- 스테이션 결과 화면
  - 날짜별 코스 기록
  - 활동별 완료 수
  - 반응 시간 변화
  - **손 유지 시간 지표는 넣지 않는다.**
- 보호자·복지사용 폰 앱(PWA) 연동
  - 사용자를 등록할 때 그 사용자 전용 QR로 한 번 연결한다. **사용자마다 연결 코드**를 따로 만든다 (2026-11-13 변경, 처음에는 스테이션 하나에 코드 하나). 그 보호자 폰에는 그 사용자의 요약만 간다.
  - 로그인할 때는 QR을 보여 주지 않는다. 보호자를 나중에 추가하거나 다시 연결할 때는 대시보드의 "보호자 연결 QR 보기"로 한다.
  - 코스가 끝나면 요약을 자동으로 보낸다. 인터넷이 없으면 대기열에 쌓았다가 연결되면 보낸다.
  - 클라우드는 Supabase.
  - 담당 B 경민 (2026-11-13 회의), **11/26 점검 전까지** 목표 (2026-11-13 변경, 처음에는 3회차 멘토링 전까지). 점검에서 코스가 끝나면 요약이 전송되는 것까지 보여 준다.
- 개인정보 (2026-11-13 변경: 얼굴 로그인이 들어가면서 "개인정보를 받지 않는다"에서 "실명은 받지 않고, 필요한 최소 정보만 동의를 받아 받는다"로 바꿈)
  - 실명·연락처는 받지 않는다. 사용자는 **호칭·별명**으로만 구분한다.
  - 기록은 시각 기반 ID(`userId`)로, 보호자 앱은 사용자별 연결 코드로 묶는다.
  - **얼굴 데이터는 WonderCam 모듈 안에만** 둔다. 라즈베리파이·Supabase에 얼굴 사진·특징값을 저장하거나 보내지 않는다.
  - 얼굴은 민감정보라 다른 동의와 **따로** 동의를 받는다. 동의하지 않아도 호칭 버튼으로 이용할 수 있다. 동의서 문구·보관 기간·삭제 방법은 #83.
  - 호칭을 Supabase에도 올릴지, `userId`만 올릴지는 보호자 앱 설계(#62)에서 정한다.
- 어르신은 폰을 조작하지 않는다.

## 4-1. 얼굴 로그인 (2026-11-13)

- 로그인은 **코스 시작 때만** 한다. STEP 하나만 할 때는 로그인 없이 지금처럼 한다.
- 로그인 방법
  - 얼굴: WonderCam이 같은 얼굴 번호를 **1.5초** 연속으로 보면 확정하고 "○○님 맞으세요?"를 묻는다 (값은 실물 테스트 때 조정).
  - **"아니요" 한 번이면 바로 호칭 버튼**으로 넘어간다. 미등록 얼굴, 인식 실패, 얼굴 동의 안 함도 호칭 버튼으로 고른다.
  - **손님 모드**: 등록하지 않아도 코스를 할 수 있다. 기록의 `userId`는 `null`.
- 사용자 등록은 복지사(진행자)가 한다: 얼굴 동의 → 호칭 적기 → 얼굴 학습 → 보호자 연결 QR.
- 시연은 실제 어르신 대신 **노인 사진**(AI로 만든 가상 인물 사진이나 이용이 허락된 사진 권장)으로 한다. 필요하면 팀원 얼굴.
- 11/26 점검 목표: 로그인 + 얼굴 실물(사진)까지. **최소 보장선은 Mock 얼굴 + 호칭 버튼 + 손님 + 사용자별 기록.**
- 화면 표현 원칙(6번, "활동 기록"만)은 그대로다. 점수표 표현은 멘토 피드백 팀 회의에서 따로 정한다.
- 카메라 배치(로그인 때 사진을 WonderCam 높이로 내려 보여 주기 / AIHand를 올리기)와 학습 방법(웹 명령 / 카메라 버튼)은 실물 확인(#76) 뒤 정한다.

관련 Issue: #75~#85 (A: #75~#78·#82, C: #79~#81·#83~#85)

## 5. 음성

- 먼저 **음성 안내** 기능을 넣는다.
  - 라즈베리파이 Chromium에 한국어 음성이 없으면 미리 녹음한 음성 파일로 바꾼다.
- 시간이 남으면 **간단한 소통**(네, 아니요, 다시 같은 몇 단어)을 인터넷 없이 연결한다.

## 6. 표현 원칙

- 화면에는 평가·진단처럼 보이는 말 대신 "활동 기록"으로만 표현한다.
