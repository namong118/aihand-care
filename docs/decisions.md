2026-11-13까지 팀이 확정한 내용. 새로 정하거나 바꾸면 날짜와 함께 이 문서를 고친다.

## 0. 앱 이름 (2026-11-16)

- 앱 이름은 **손잇다**, 영문 표기는 **SON:IT**. 발표 자료에는 "손잇다 (SON:IT)"처럼 한글과 함께 적는다
- 쌍점(:)은 화면에 보이는 이름에만 쓴다. 파일 이름·주소에는 `sonit`을 쓴다 (예: `public/icons/sonit-192.png`)
- 저장소 이름, 배포 주소(`/aihand-care/`), localStorage 키(`aihand-care.*`)는 바꾸지 않는다. 바꾸면 쌓인 기록과 키오스크 주소가 끊긴다
- 앱 아이콘: 남색 바탕에 흰 손. `public/icons/sonit-32·64·180·192·512.png`. 바탕이 꽉 찬 정사각형이고 손이 가운데 80% 안에 있어 보호자 앱(PWA)의 `maskable` 아이콘으로도 쓸 수 있다

## 1. 시연 형태

- 로봇손 앞에 두는 **전용 스테이션**으로 시연한다.
  - 라즈베리파이 5 + Touch Display 2 (7인치, 보드는 디스플레이 뒷면에 붙임) + Active Cooler
  - 웹캠: 로지텍 C270
  - USB 스피커폰: 자브라 스피크 510
- 전원을 켜면 Chromium **키오스크 모드**로 앱이 전체 화면으로 자동 실행된다.
  - 시크릿 모드(`--incognito`)는 쓰지 않는다. 활동 기록을 유지하기 위해서다.
- 스테이션은 **인터넷 없이** 동작한다.
  - 앱은 라즈베리파이 로컬에서 실행한다.
  - MediaPipe wasm·모델과 글꼴도 로컬에 둔다.
  - 시연 때는 **휴대폰 핫스팟(아이폰)을 켜 둔다** (2026-11-13). 라즈베리파이에 RTC 배터리가 없어 켤 때 인터넷으로 시계를 맞춰야 하고, 보호자 앱 요약도 바로 보내기 위해서다. 핫스팟이 끊겨도 앱은 그대로 동작한다.
- 난이도와 설정은 대시보드에서 조정한다.

관련 문서: `README.md` "라즈베리파이 준비", `docs/hardware-check.md` 5번 (라즈베리파이 FPS·GPU 측정)

## 2. 미션맵 배치

- AIHand는 세워서 두고, 웹캠은 로봇 받침대 바로 앞에 둔다.
- 손 인식과 카드 보여 주는 자리는 **로봇 앞 같은 위치 한곳**이다. 웹캠과 WonderCam이 같은 자리를 본다.
- 숫자 카드는 **WonderCam 숫자 인식 모드**로 읽는다 (AprilTag 태그 방식이 아니다).
- 색깔 카드(STEP 3)는 AprilTag 태그 모드(펌웨어 F2)로 읽는다. 임시 결정이며 종이 카드로 확인한 뒤 확정한다 (#17).

관련 문서: `docs/hardware-check.md` 4번·부록 8 (숫자 인식 확신도·거리)

## 3. 시연 코스

- 순서: **손운동(STEP 4) → 가위바위보(STEP 2) → 숫자 기억(STEP 1) → 색깔손(STEP 3)**
  - 이유: 손으로 하는 활동 → 카드로 하는 활동 (입력 방식이 한 번만 바뀐다), 쉬운 것 → 어려운 것
- STEP 번호와 폴더명(`step1-memory` 등)은 바꾸지 않는다. 화면에는 코스 순서("1번째 활동")로 보여 준다.
- 시너지 설명
  - 순서 자체의 이유 (위)
  - 활동마다 다른 역할

    | 활동 | 역할 |
    |---|---|
    | 손운동 | 모방·움직임 |
    | 가위바위보 | 조건 판단 |
    | 숫자 기억 | 순서 기억 |
    | 색깔손 | 주의 전환 |
- **맞춤 단계** (2026-11-26 변경, 팀 동의. 처음에는 "앞 결과로 다음 활동 맞춤 조정"을 보류로 뺐다)
  1. **처음 시작 단계 추천**: "나의 시작 찾기"(PR #146)로 짧게 해 보고 활동마다 시작 단계(난이도·도전 단계)를 정한다
  2. **시작 단계는 로그인한 분마다** 저장하고, 그분이 코스를 시작하면 그 단계로 한다. 손님(`userId` 없음)은 홈의 지금 설정 그대로
  - 단계는 코스 중간에 바꾸지 않는다. 코스를 시작할 때 정한다
  - 코스는 대시보드가 진행하므로 단계도 대시보드가 `ctx.settings`(`difficulty`, `challengeLevel`)로 넘긴다. 프로그램은 왜 그 단계인지 몰라도 된다
  - **자동으로 단계를 올리지 않는다** (2026-11-26 멘토링: "며칠 동안 잘 해내시면 올리기"는 기준을 잡기 어렵다). 발표에서도 앱이 알아서 올려 준다고 말하지 않는다
  - **시연: 시작 단계가 다른 예시 세 분** (멘토 제안). 나의 시작 찾기의 추천 세 가지와 같게 둔다

    | 예시 | 기본 활동 | 도전 활동 |
    |---|---|---|
    | 첫째 분 | 쉬움부터 | 1단계 |
    | 둘째 분 | 보통부터 | 1단계 |
    | 셋째 분 | 어려움부터 | 2단계 |

    - 세 분을 사용자로 등록하고(호칭, AI로 만든 노인 사진으로 얼굴 학습) **시작 단계만** 다르게 둔다. 지어낸 지난 기록은 넣지 않는다
  - 표현 원칙(6번)은 그대로: 사람을 "1번 수준"처럼 나누지 않는다. "쉬움부터 시작하시는 분"처럼 단계를 주어로 쓰고, 사람은 호칭으로만 부른다. "실력이 올랐어요", "등급" 같은 판정 표현도 쓰지 않는다
  - **단계 바꾸기는 두 가지 모두** 된다: 설정에서 그분의 단계를 바꾸기, 나의 시작 찾기를 다시 하기
  - **손운동**: 기본 활동(손운동 코칭)에는 난이도를 넣지 않고 세 분 모두 같게 한다. 차이는 짝 도전 활동 **공 주고받기**의 1·2·3단계로 둔다. 공 주고받기는 A가 이어서 만든다 (2026-11-26, 처음에는 B "시간이 남으면")
- **보류** (지금 범위에서 뺌)
  - 손모양 이어지기 (앞 활동의 손모양이 뒤 활동에 다시 나오기)
  - 오늘의 손모양 회상 (코스 처음에 보고 끝에 떠올리기)

## 4. 기록과 보호자 앱

- 스테이션 결과 화면
  - 날짜별 코스 기록
  - 활동별 완료 수
  - 반응 시간 변화
  - **손 유지 시간 지표는 넣지 않는다.**
- 보호자·복지사용 폰 앱(PWA) 연동
  - 사용자를 등록할 때 그 사용자 전용 QR로 한 번 연결한다. **사용자마다 연결 코드**를 따로 만든다 (2026-11-13 변경, 처음에는 스테이션 하나에 코드 하나). 그 보호자 폰에는 그 사용자의 요약만 간다.
  - 로그인할 때는 QR을 보여 주지 않는다. 보호자를 나중에 추가하거나 다시 연결할 때는 대시보드의 "보호자 연결 QR 보기"로 한다.
  - 코스가 끝나면 요약을 자동으로 보낸다. 인터넷이 없으면 대기열에 쌓았다가 연결되면 보낸다.
  - 클라우드는 Supabase.
  - 담당 B 경민 (2026-11-13 회의), **11/26 점검 전까지** 목표 (2026-11-13 변경, 처음에는 3회차 멘토링 전까지). 점검에서 코스가 끝나면 요약이 전송되는 것까지 보여 준다.
- 개인정보 (2026-11-13 변경: 얼굴 로그인이 들어가면서 "개인정보를 받지 않는다"에서 "실명은 받지 않고, 필요한 최소 정보만 동의를 받아 받는다"로 바꿈)
  - 실명·연락처는 받지 않는다. 사용자는 **호칭·별명**으로만 구분한다.
  - 기록은 시각 기반 ID(`userId`)로, 보호자 앱은 사용자별 연결 코드로 묶는다.
  - **얼굴 데이터는 WonderCam 모듈 안에만** 둔다. 라즈베리파이·Supabase에 얼굴 사진·특징값을 저장하거나 보내지 않는다.
  - 얼굴은 민감정보라 다른 동의와 **따로** 동의를 받는다. 동의하지 않아도 호칭 버튼으로 이용할 수 있다. 동의서 문구·보관 기간·삭제 방법은 #83.
  - **Supabase에는 `userId`만 올린다.** 호칭·사용자 목록은 올리지 않고, 호칭은 QR 주소로 보호자 폰에만 전한다 (2026-11-18, #62).
- 어르신은 폰을 조작하지 않는다.
- 보호자 앱 설계에서 정한 것 (2026-11-18, PR #118 리뷰. 자세한 내용은 `docs/guardian-app.md` 10번)
  - **스테이션 비밀값**: 스테이션이 부르는 Supabase 함수 4개(연결·요약 보내기·연결 끊기·사용자 지우기)는 비밀값으로 막는다. 비밀값은 **라즈베리파이 `.env.local`에만** 두고, Supabase에는 해시만 둔다. GitHub Pages 배포에는 넣지 않으므로 배포 주소에서는 보내기가 Mock으로 동작한다.
  - 비밀값이 든 앱 서버는 같은 네트워크에 열지 않는다. 키오스크는 `127.0.0.1`로만 켜고, 개발 PC도 `npm run dev`를 `--host`로 켜지 않는다.
  - Supabase는 새 패키지(`supabase-js`) 없이 `fetch`로만 부른다. QR은 `qrcode` 패키지(MIT)로 그린다 (라즈베리파이에서 인터넷 없이).
  - 계정: 경민 계정 조직에 남영 초대. 배포 주소는 저장소 Variables(공개 키만), 라즈베리파이는 `.env.local`.
  - 폰 앱 화면: 첫 화면은 월 달력 + 이모지(연속 기록 표시 없음), 그 아래 모아 보기(참여, 반응 시간 변화). 회차 화면은 코스 요약(시간 + 활동 수), 회차 그래프, 스텝별 요약(어떻게 했는지 + STEP 4 루틴). 하루에 여러 번 한 날은 회차 탭.
  - 정답률, 인지 능력 이름을 축으로 한 방사형 그래프, 정상 기준선은 넣지 않는다 (6번 표현 원칙). 폰 앱 본문은 16px 이상. 푸시 알림은 이번 범위에서 뺀다.
  - 스테이션의 보호자 연결 끊기 버튼은 "보호자 연결 QR 보기"에 둔다 (점검 뒤).
  - 아직 정할 것: 활동·참여를 축으로 한 방사형 그래프(#117과 함께 멘토 피드백 회의에서. 정할 때까지 폰 앱에 넣지 않음). 사용자 지우기 화면은 A가 만든다 (2026-11-26).

## 4-1. 얼굴 로그인 (2026-11-13)

- 로그인은 **코스 시작 때만** 한다. STEP 하나만 할 때는 로그인 없이 지금처럼 한다.
- 로그인 방법
  - 얼굴: WonderCam이 같은 얼굴 번호를 **1.5초** 연속으로 보면 확정하고 "○○님 맞으세요?"를 묻는다 (값은 실물 테스트 때 조정).
  - **"아니요" 한 번이면 바로 호칭 버튼**으로 넘어간다. 미등록 얼굴, 인식 실패, 얼굴 동의 안 함도 호칭 버튼으로 고른다.
  - **손님 모드**: 등록하지 않아도 코스를 할 수 있다. 기록의 `userId`는 `null`.
- 사용자 등록은 복지사(진행자)가 한다: 얼굴 동의 → 호칭 적기 → 얼굴 학습 → 보호자 연결 QR.
- 시연은 실제 어르신 대신 **노인 사진**(AI로 만든 가상 인물 사진이나 이용이 허락된 사진 권장)으로 한다. 필요하면 팀원 얼굴.
- 11/26 점검 목표: 로그인 + 얼굴 실물(사진)까지. **최소 보장선은 Mock 얼굴 + 호칭 버튼 + 손님 + 사용자별 기록.**
- 화면 표현 원칙(6번, "활동 기록"만)은 그대로다. 점수표 표현은 멘토 피드백 팀 회의에서 따로 정한다.
- 실물 확인(#76, 2026-11-15) 뒤 정함
  - 카메라 배치: 로그인 때 **사진을 WonderCam 높이로 내려 보여 준다**. AIHand 위치는 그대로
  - 학습 방법: **카메라 레버**로 한다 (I2C 학습 명령이 없다). 웹은 번호만 받는다
  - 시연 사진은 **생김새가 확실히 다른** 사진으로 고른다 (비슷한 사진은 번호가 번갈아 나와 확정되지 않았다)
  - 자세한 결과: `docs/hardware-check.md` 4-1

관련 Issue: #75~#85 (A: #75~#78·#82, C: #79~#81·#83~#85)

## 5. 음성

- 먼저 **음성 안내** 기능을 넣는다.
  - 라즈베리파이 Chromium에 한국어 음성이 없으면 미리 녹음한 음성 파일로 바꾼다.
- 시간이 남으면 **간단한 소통**(네, 아니요, 다시 같은 몇 단어)을 인터넷 없이 연결한다.

## 6. 표현 원칙

- "치매 예방", "인지 기능 향상", "효과", "치료" 같은 표현을 앱과 발표에 쓰지 않는다.
- 화면에는 평가·진단처럼 보이는 말 대신 "활동 기록"으로만 표현한다.
- 근거 자료: `docs/research/evidence.md` (발표에서 쓸 수 있는 문장 / 쓰면 안 되는 표현 포함)
