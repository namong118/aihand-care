# STEP 3 색깔손 (step3-stroop)

- **담당:** C
- 이 폴더 밖 파일은 고치지 않는다. 필요하면 이유를 설명하고 담당 A에게 확인받는다.

## 목적

색 이름 글자(예: "파랑")를 다른 색(예: 빨간색)으로 보여주고,
글자의 **뜻이 아니라 글자 색**과 같은 **색깔 카드를 AIHand의 WonderCam에 보여주는** 활동 (스트룹 과제 형식).
교육·체험용 활동이며, 치료·예방 효과를 주장하지 않는다.

## 입력

- **색깔 카드:** `ctx.card.onCard(cb)` → `cb({ color })`
  - `color`는 `'red'` · `'blue'` · `'yellow'` · `'green'` 중 하나
  - STEP 3는 **카드 ID를 모른다.** ID→색 변환은 `core/card` 안에서만 한다 (`core/card/tags.json`은 쓰지 않는다)
  - 화면에 쓸 색 이름·표시 색은 `src/data/colors.json` (`{ color, label, hex }`)
  - Mock: 오른쪽 패널 "색 카드 — 카드 대신 입력(Mock)" 버튼 또는 키보드 `R`/`B`/`Y`/`G`
  - 실제: 펌웨어 F2부터 AprilTag 태그 모드(`TAG,<번호>` → `core/card`가 색으로 바꿈). 종이 카드 인식 거리·조명은 **[검증 필요]** (`docs/hardware-check.md` 4번). 어느 방식이든 `{ color }` 형태는 같아서 이 폴더 코드는 바뀌지 않는다
- **화면 버튼:** 카드 인식이 안 될 때를 위한 대체 입력. 색 막대와 함께 "빨강" 같은 글자를 꼭 표시한다

## 해야 할 기능

- [x] 문제 만들기 `makeQuestion` (쉬움: 뜻=색, 보통: 섞임, 어려움: 항상 다름), 판정 `judge` (테스트 있음)
- [x] 문제 1개 → 입력(색깔 카드 또는 화면 버튼) → 판정 → 로봇 반응 → 기록
- [x] 한 회차 여러 문제(`makeRound`, 기본 5문제, 같은 문제 연달아 안 나옴), 문제 사이 간격(`gapMs`), 진행 표시(예: 2 / 5)
- [ ] 카드를 잠깐 스치듯 보여줬을 때도 답으로 칠지 정하기 (실물 카드 인식 확인 후)
- [ ] 색 구분이 어려운 사용자를 위한 안내 (아래 참고)
- [x] 로봇의 역할: 회차 시작 신호로 `ctx.robot.hello()`, 문제마다 `react('ok' | 'retry')`, 모두 맞히면 `hello()` 한 번 더 (`isPerfect`)
- [x] 답이 `NO_ANSWER_HINT_MS`(10초) 동안 없으면 "카드를 내렸다가 다시 보여 주세요" 안내 (#14 카드를 들고 있으면 다시 인식하지 않음)
- [x] 회차 시작 때 `ctx.card.ready()`로 카메라가 태그 모드가 될 때까지 기다림 (STEP 1 숫자 모드 다음이면 최대 약 5초)
- [x] 말소리(`voice.js`): 문제·결과 문구를 브라우저 음성으로 읽어 줌. 글자 뜻은 읽지 않음. 지원하지 않으면 조용히 넘어감

## 접근성 메모

이 활동은 색 자체를 보는 과제라서 문제 글자는 색으로만 구분된다. 대신:

- 답하는 버튼에는 항상 색 이름 글자를 함께 쓴다. 실물 카드에도 색 이름을 인쇄하는 것을 권한다.
- 노랑이 잘 보이도록 글자는 어두운 배경(`.stroop-stage`) 위에 표시한다.
- 시작 전에 "색 구분이 어려우시면 다른 활동을 골라도 돼요" 같은 안내를 넣을지 팀에서 정한다.

## 기록 (`ctx.log.record`)

한 회차(여러 문제)가 끝날 때 한 번 기록한다. `total`은 문제 수, `done`은 맞힌 수, `avgReactionMs`는 문제별 반응 시간의 평균.

공통 필드 + `detail: { difficulty, questions: [{ word, ink, congruent, picked, pickedWord, inputVia, reactionMs }, ...] }`
(`word`·`ink`·`picked`는 `'red'` 같은 색 이름, `inputVia`는 `'card'` 또는 `'button'`)

## 하지 말아야 할 것

- `src/core/`를 import 하거나 고치지 않는다. **`ctx`만 사용한다.**
- 카드 ID(태그 번호)를 다루지 않는다. 색(`color`)만 쓴다.
- `logic.js`에서 DOM이나 `ctx`를 쓰지 않는다.
- WonderCam 카드 인식이 되는 것처럼 가정하지 않는다. 검증 전까지는 Mock과 화면 버튼으로 동작해야 한다.
- "틀렸습니다", "실패" 대신 "다시 해 볼까요?"를 쓴다.
