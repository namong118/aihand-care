# STEP 4 손운동 코칭 (step4-coach)

- **담당:** B
- 이 폴더 밖 파일은 고치지 않는다. 필요하면 이유를 설명하고 담당 A에게 확인받는다.
  (루틴 데이터 `src/data/routines.json`을 바꿀 때도 먼저 확인받는다.)

## 목적

로봇이 손운동 시범을 보여주면 사용자가 **보면서 함께 따라 하는** 활동.
교육·체험용 활동이며, 치료·재활·예방 효과를 주장하지 않는다.

## STEP 1과 STEP 4의 차이

| | STEP 1 기억손 | STEP 4 손운동 코칭 |
|---|---|---|
| 핵심 | **기억 후 재현** | **보면서 반복** |
| 로봇 | 보여준 뒤 손을 내린다. 따라 할 때는 정답이 안 보인다 | 시범 손모양을 든 채로 있고, 사용자가 동시에 따라 한다 |
| 판정 | 순서·손모양이 맞았는지 | 따라 했는지만 센다. **맞고 틀림을 따지지 않는다** |
| 기록 | `done` = 정답 문제 수 | `done` = 따라 한 동작 수, `skipped` = 건너뛴 수 |

그래서 STEP 4에는 "다시 해 볼까요?" 반응이 없다. 끝나면 항상 칭찬(`react('ok')`)한다.

## 입력 확정 기준 (지금 값)

- `ctx.hand.waitForPose({ holdMs: 루틴 holdMs, since: 동작 시작 시각, names: [시범 손모양] })`로 확인
- 시범과 같은 손모양을 루틴의 `holdMs`(기본 1초) 이상 유지하면 그 동작 완료. 동작이 시작된 뒤에 만든 손모양만 인정 (공통 규칙)
- 유지 게이지는 `ctx.hand.onPose`의 `stableMs`로 그린다 (확정 규칙과 똑같이, 시작 전부터 들고 있던 손은 0)
- 손 인식이 어려울 때를 위해 "따라 했어요" 버튼(대체 입력)과 "건너뛰기" 버튼을 둔다

### 루틴 반복 (`repeat`)

- 한 회차 안에서 루틴의 `steps`를 되풀이하는 횟수. 팀원이 `routines.json`에 적는다 (사용자가 입력하지 않음)
- `repeat`이 0 이하이거나 없으면 1번 한다 (2026-11-12 결정, `logic.test.js`로 지킴)

### 숫자 세기·쉬는 시간 (2026-11-12 결정)

- 숫자 세기("하나, 둘, 셋")는 **손모양을 유지하는 동안** 1초에 하나씩 센다 (`holdCount`, `countWord`). 쉬는 시간에 세지 않는다
- 몇까지 셀지는 `holdMs`를 따른다 (1초 → 하나, 3초 → 하나·둘·셋). 코드에 초를 박지 않는다
- 유지 시간은 **지금 1초 그대로**. 기능이 완성된 뒤 3초로 바꿀지 정하고, 바꿀 때는 `routines.json` 담당 확인을 받는다
  - 3초로 늘리면 손 인식이 잠깐 흔들릴 때 처음부터 다시 셀 수 있다 (공통 규칙: code 가 바뀌면 `stableMs` 0). 실제 웹캠으로 시험한 뒤 정한다
- 동작 사이 쉬는 시간: `restMs(speed)` = 2초, 느리게(SLOW)면 4초. 건너뛴 뒤에도 쉰다 (1초는 짧다는 담당자 의견으로 2초)

### 화면 안내 (2026-11-12 결정)

- 동작 화면: "동작 3 / 4 · 반복 2 / 2"(반복이 1번이면 반복 표시 없음), 숫자 세기 글자, 유지 게이지와 초 글자
- **미리 든 손 안내**: 시범과 같은 손모양을 동작 시작 전부터 들고 있으면(`holdState` = `'old'`) 게이지가 차지 않는다 (공통 규칙). 이 상태가 1초 계속되면(`OLD_HAND_NOTICE_MS`, STEP 2와 같은 기준) "손을 잠깐 내렸다가 다시 해 주세요"를 띄운다. 확정 규칙은 바꾸지 않고 알려 주기만 한다
  - 로봇이 시범 손모양을 든 채로 있어서, 시범을 보며 바로 따라 하면 이 상태가 되기 쉽다. 같은 손모양이 연달아 나오는 루틴(동작 2 → 4 모두 손바닥 등)도 마찬가지
- 쉬는 시간 화면: "좋아요!" 또는 "건너뛰었어요. 괜찮아요." + 다음 동작 안내
- "시작하기"·"한 번 더 하기"는 한 번 누르면 잠긴다 (두 번 눌러 회차가 두 개 도는 것 방지)

### 루틴 고르기 (2026-11-13 결정)

- 루틴이 2개 이상이면 STEP 4에 들어가자마자 **루틴 고르는 화면**을 보여 준다. 1개면 바로 그 루틴 소개
- 루틴 카드를 나란히 보여 준다. 넓은 화면에서 2열이라 루틴 4개면 2×2. 홈 활동 카드와 같은 클래스(`home-grid`, `home-card step4`)를 쓴다
  - 카드: 제목, "동작 N개"(반복 포함, `stepCountOf`), "고르기 ›" 표시, 설명(24px). **카드 전체가 버튼 하나**다
  - 시연 화면(1280×720, 실제 AIHand 연결)에서 카드 4개가 스크롤 없이 다 보여야 한다. 그래서 카드 아래 64px 버튼을 따로 두지 않는다 (11/13 확인: 카드 맨 아래 y=622). 가상 로봇손 칸이 붙는 Mock 화면은 폭이 좁아 스크롤이 생긴다
  - 루틴 설명이 길어지면 카드가 높아진다. 설명은 시연 화면에서 2줄 안쪽(띄어쓰기 포함 50자쯤, 지금 가장 긴 "손가락 숫자 세기" 설명이 딱 2줄)으로 쓴다
- 모든 루틴은 **동등하게** 고른다. 추천 표시나 순서 고정을 하지 않는다 ("하루 마무리"도 같은 카드)
- 시연 코스(STEP 4가 1번째 활동)에서도 같은 고르는 화면이 나온다. STEP 4는 코스인지 모른다 (#59: 프로그램 코드는 바꾸지 않음). 시연 때 하나를 골라 진행한다
- 루틴 소개와 회차 끝에 "다른 손운동 고르기" 버튼 (루틴이 2개 이상일 때만). 회차 끝의 두 버튼은 먼저 누른 하나만 동작

### 음성 안내 (2026-11-13 결정)

- 팀 결정(`docs/decisions.md` 5번)대로 넣는다. 2026-11-12에 정했던 "말소리 넣지 않음"은 이 결정으로 바뀌었다
- **#61 결과를 보고 넣는다.** 라즈베리파이 한국어 음성이 있으면 브라우저 음성, 없으면 녹음 파일. STEP 2·3의 `voice.js`를 STEP 4에 다시 복사하지 않고, 공통 모듈이 생기면 그것을 쓴다
- 음성은 화면 글자를 대신하지 않는다 (글자도 함께 표시)
- 읽을 것 (녹음 파일 방식이면 이 문장들이 녹음 목록이 된다)

  | 때 | 읽을 말 |
  |---|---|
  | 동작 화면이 뜰 때 | 루틴의 `say` |
  | 따라 했을 때 | "좋아요" |
  | 건너뛰었을 때 | "괜찮아요" |
  | 미리 든 손 안내가 뜰 때 | "손을 잠깐 내렸다가 다시 해 주세요" |
  | 회차가 끝났을 때 | "함께 마쳤어요. 수고하셨어요" |

- 숫자 세기("하나")는 **읽지 않는다**. 1초마다 말하면 시끄럽고 `say`와 겹친다

### 완료 방식 (`method`)

| 값 | 뜻 |
|---|---|
| `detected` | 손 인식으로 따라 한 것이 확인됨 |
| `manual` | 사용자가 "따라 했어요" 버튼을 누름 (손 인식은 확인 못 함) |
| `skipped` | 건너뜀 |

`done` = `detected` + `manual`. 시연·발표 때 "손 인식으로 확인된 동작"과 "버튼으로 넘어간 동작"을 구분해서 말할 수 있게 둘을 나눠 기록한다.

## 기록 (`ctx.log.record`)

공통 필드(`total` = 동작 수, `done` = 따라 한 수, `skipped` = 건너뛴 수) +

```js
detail: {
  routine: 'basic-grip',
  methods: { detected: 2, manual: 1, skipped: 1 },          // 결과 화면 "자세히" 칸
  steps: [{ pose: 'ROCK', method: 'detected', reactionMs: 1200 }, ...],
}
```

## 하지 말아야 할 것

- `src/core/`를 import 하거나 고치지 않는다. **`ctx`만 사용한다.**
- `logic.js`에서 DOM이나 `ctx`를 쓰지 않는다.
- 무리하게 반복을 강요하는 문구를 쓰지 않는다. 건너뛰기를 항상 허용한다.
- 운동 효과·재활 효과를 말하는 문구를 쓰지 않는다.
