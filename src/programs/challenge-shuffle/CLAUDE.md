# 도전 활동: 카드 섞기 (challenge-shuffle)

- **담당:** C
- 계획: #132
- 이 폴더 밖 파일은 고치지 않는다 (`src/programs/index.js` 한 줄 등록만 C가 함). 필요하면 #132에 댓글로 A에게 확인받는다.

## 목적

빨·파·노·초 카드 4장이 화면에서 **뒤집혀 섞이고**, 로봇이 손가락으로 "3번 자리"를 물으면 그 자리 카드 색을 **색깔 카드로** 답하는 도전 활동.
움직이는 것을 눈으로 따라가는 활동이고, 섞는 횟수가 많아질수록 어려워진다. 교육·체험용 활동이며, 치료·예방 효과를 주장하지 않는다.

- 홈의 **색깔손 카드 아래 "도전" 칸**에서 열린다 (홈은 A 담당). 코스에는 들어가지 않는다
- 화면에는 "야바위"라는 말을 쓰지 않고 "카드 섞기"로 쓴다. "놀이"라는 말 대신 "도전 활동"
- STEP 3 색깔손(`step3-stroop`) 코드는 import 하지 않는다. 필요한 것은 이 폴더에 따로 둔다

## 진행

1. 시작 화면에서 단계 고르기 (아래 "단계")
2. 카드 4장이 앞면(색 + 색 이름 글자)으로 한 줄. 카드 아래 자리 번호 **1~4**는 고정 (코드 안에서는 0~3)
3. "카드를 잘 보세요" 2초 (속도 느리게 3초, `showMs`) → 4장 모두 뒤집힘 (뒷면은 4장 모두 같은 무늬)
4. 두 장씩 자리를 바꾸며 섞임. **한 번에 한 장만 움직인다:** ① 앞 카드가 들려서 상대 자리 위로 → ② 상대 카드가 빈자리로 → ③ 들린 카드가 내려옴 (`moveMs`, `moveMs`, `moveMs × 0.6`)
5. 로봇이 손가락으로 자리를 묻는다: 1 `INDEX` · 2 `V` · 3 `THREE` · 4 `FOUR` (`positionPose`). 화면에도 그 자리를 테두리와 "▲ 3번" 글자로 표시
6. 색깔 카드(또는 화면 버튼)로 답 → 그 자리 카드를 뒤집어 보여 줌 → `react('ok' | 'retry')`. 다른 색이어도 **다시 묻지 않는다** ("여기에는 파랑이 있었어요")
7. 묻는 자리가 2곳이면 5~6을 한 번 더 (같은 자리는 다시 묻지 않음, `pickAsks`)
8. 판 끝에 4장 모두 앞면으로. **한 회차 5판** (`ROUNDS`) → 끝 화면 → 기록 한 번

## 단계

| 단계 | 섞는 횟수 | `moveMs` | 묻는 자리 |
|---|---|---|---|
| 1단계 | 4 | 1000 | 1곳 |
| 2단계 | 6 | 800 | 2곳 |
| 3단계 | 8 | 600 | 2곳 |

- 시작 화면에서 고른다 (도전 활동 공통 부품 `src/ui/level-picker.js`의 `levelPicker`, A). **미리 선택**은 `ctx.settings.challengeLevel`(1·2·3, 나의 시작 찾기·사람별 시작 단계로 대시보드가 넣음), 없으면 1단계 (`defaultLevel`)
- **나의 시작 찾기 짧은 판** (`ctx.settings.findStart`가 `true`, 2026-11-26 A): 단계 고르기 없이 **1단계 2판** (`roundCount`, `FIND_START_GAME`). 둘 다 같은 색을 고르셔야 "해냄". 기록은 평소와 같고 대시보드가 `detail.findStart`를 붙인다
- 홈의 난이도(`ctx.settings.difficulty`, 기본 활동용)는 **쓰지 않는다**. 속도 느리게(`ctx.settings.speed === 'SLOW'`)면 `moveMs` ×1.5 (`levelSpec`)
- 바로 앞 섞기와 같은 쌍은 연달아 바꾸지 않는다 (`makeSwaps`)
- 3단계가 너무 쉬우면 섞는 횟수를 10~12번으로 늘려 본다 (속도는 그대로)

## 입력

- **색깔 카드:** `ctx.card.onCard(cb)` → `cb({ color })`. 카드 ID는 모른다
  - 회차 시작 때 `onCard` 구독 후 `await ctx.card.ready()` (WonderCam 태그 모드가 될 때까지)
  - 답은 물을 때만 받는다. **섞는 동안 보여 준 카드는 버린다** (그때는 `onCard`를 구독하지 않음)
  - 답을 기다린 지 10초(`NO_ANSWER_HINT_MS`)가 지나면 "카드를 내렸다가 다시 보여 주세요" 안내 (#14)
  - Mock: 키보드 `R`/`B`/`Y`/`G` 또는 Mock 패널 버튼
- **화면 버튼:** 카드 대체 입력. 색 칸과 함께 "빨강" 같은 글자를 꼭 표시한다

## 로봇

회차 시작 `hello()` → 묻기마다 `showPose(positionPose(p))` (손이 움직이는 동안에도 답은 받음) → 답 뒤 `react(...)` → 끝 `rest()`

## 화면

- 애니메이션은 브라우저 내장 `element.animate()`로 카드의 `transform`만 움직인다 (`top`·`left`를 바꾸지 않음, 라즈베리파이에서 가볍게). 새 패키지 없음
- 판정은 계산한 배치(`applySwaps`)로 한다. 화면에서 움직인 결과와 다르면 콘솔에 경고
- 카드·자리 모양은 공통 스타일을 고치지 않고 `screen.js`에서 `style`로 준다
- `unmount()`에서 타이머, 카드 구독, 진행 중인 애니메이션을 모두 멈춘다
- 1280×720 기준: 묻는 화면의 답 버튼 아래 끝 약 624px (2026-11-20 Mock)

## 기록 (`ctx.log.record`)

회차가 끝날 때 한 번. 끝까지 하지 않은 회차는 기록하지 않는다.
`total`은 물은 횟수(5판 × 묻는 자리 수), `done`은 같은 색을 고른 수, `avgReactionMs`는 묻고 나서 답까지의 평균.

```js
detail: {
  level,   // 1 | 2 | 3
  speed,   // 'NORMAL' | 'SLOW'
  rounds: [{ start, swaps, final, asks: [{ position, answer, picked, correct, inputVia, reactionMs }] }],
}
```

(`start`·`final`은 자리 0~3의 색, `swaps`는 `[[0, 2], ...]`, `position`은 0~3, `inputVia`는 `'card'` 또는 `'button'`)

끝 화면에도 점수·정답률처럼 쓰지 않는다 ("물어본 카드 10장 가운데 7장의 색을 찾아 주셨어요").
