# STEP 2 사고력 가위바위보 (step2-rps)

- **담당:** D
- 이 폴더 밖 파일은 고치지 않는다. 필요하면 이유를 설명하고 담당 A에게 확인받는다.

## 목적

로봇이 낸 가위바위보와 화면의 조건을 보고, 조건에 맞는 손을 생각해서 내는 활동.
단순한 가위바위보가 아니라 "조건을 읽고 → 결과를 거꾸로 생각해 → 손을 내는" 과정이 핵심이다.
교육·체험용 활동이며, 치료·예방 효과를 주장하지 않는다.

## 조건 5종 (원래 기획, 바꾸지 않는다)

| id | 화면 문구 | 사용자가 만들어야 할 결과 |
|---|---|---|
| `WIN` | 이겨주세요 | 이김 |
| `LOSE` | 져주세요 | 짐 |
| `DRAW` | 비겨주세요 | 비김 |
| `NO_WIN_NO_DRAW` | 이기지도 비기지도 마세요 | 짐 (= 져라) |
| `NO_LOSE_NO_DRAW` | 지지도 비기지도 마세요 | 이김 (= 이겨라) |

위 5종은 정답 손이 **정확히 하나**다. `logic.test.js`가 이것을 확인한다.

### 어려움 전용 조건 2종: 정답이 둘 (2026-11-24 D 결정, #18)

| id | 화면 문구 | 사용자가 만들어야 할 결과 |
|---|---|---|
| `NO_WIN` | 이기지 마세요 | 짐 또는 비김 |
| `NO_LOSE` | 지지 마세요 | 이김 또는 비김 |

- **어려움에만** 나온다. 쉬움·보통은 그대로
  - "~지 마세요"를 "지거나 비기면 된다"로 바꿔 생각하는 단계가 어려움에 맞다. 다만 세 손 중 둘이 정답이라 찍어서 맞을 확률은 오히려 높다 (활동 기록이지 점수가 아니므로 괜찮다고 봄)
- 정답 손이 정확히 둘인지 `logic.test.js`가 확인한다
- 판정: 조건마다 `targets`(결과 목록)를 두고 그중 하나가 되면 맞음. `judge` 반환은 `{ correct, outcome, answers }` (`answers`: 정답 손 목록, 원래 5종은 하나). `answerFor`는 `answersFor`로 바뀌었다
- 도움말: "“이기지 마세요”는 지거나 비기면 된다는 뜻이에요."
- 두 번째도 맞지 않으면: 설명 "지거나 비기려면 ✊ 바위나 ✌️ 가위를 내면 돼요." + 화면에 두 손 그림 + **로봇이 두 손을 차례로** 보여 준다 (사이에 쉬는 시간 `restMs`)
- 기록: 형식은 그대로. `detail.questions[].condition`에 `NO_WIN`·`NO_LOSE`가 새로 나올 수 있다 (정답 손은 기록하지 않음)
- 시작 안내(어려움): "“이기지 마세요”처럼 낼 수 있는 손이 둘인 문제도 나와요."

## 진행 방식 (2026-11-12 D 결정)

| 항목 | 정한 값 |
|---|---|
| 한 회차 문제 수 | 5문제 (`QUESTIONS_PER_ROUND`) |
| 로봇 연출 | 화면 큰 글자 + 음성으로 "가위" → "바위" → "보!" 뒤에 `showPose` (`voice.js`) |
| 제한 시간 | 없음. "건너뛰기" 버튼으로 넘어갈 수 있다 (`skipped`로 기록) |
| 조건에 맞지 않는 손을 냈을 때 | "다시 해 볼까요?" + 도움말 → "다시 하기"로 한 번 더 (`MAX_TRIES` = 2). 두 번째도 맞지 않으면 답과 이유를 함께 확인하고 로봇이 그 손을 보여 준다 |
| 난이도 | 쉬움: 기본 조건 3종(`WIN`·`LOSE`·`DRAW`) / 보통: 원래 5종 / 어려움: 5종 + 정답이 둘인 2종(`NO_WIN`·`NO_LOSE`, #18) + 로봇 손을 **3초**(천천히 4.5초)만 보여 주고 내림 (`revealMs`) |
| 요약 화면 | 문제별 한 줄(로봇 손 · 조건 · 결과 문구) + 격려 문구. 점수는 보여 주지 않는다 |
| 손 인식 | **웹캠**(MediaPipe, 시연: 라즈베리파이 + C270). WonderCam은 손모양 인식 기능이 없고 앱에 영상을 보내지 않아 쓰지 않는다 |
| 손 인식 안내 | 잘 될 때는 띄우지 않는다(웹캠 미리 보기의 손가락 선만). 이상이 잠깐 계속될 때만 문제 화면에 안내 (아래) |

### 손 인식 안내 (`handFeedback`, `shouldShowNotice`)

| 상황 | 안내가 뜨는 때 (`NOTICE_DELAY_MS`) | 문구 |
|---|---|---|
| 손이 안 보임 | 3초 넘게 계속 | 👋 카메라에 손이 보이지 않아요 |
| 가위바위보가 아닌 손 | 1초 넘게 계속 | 👋 가위·바위·보 중 하나를 내 주세요 |
| 문제 전부터 들고 있던 손 | 1초 넘게 계속 | 👋 ✊ 바위 — 손을 한 번 내렸다가 다시 내 주세요 |

판단은 `waitForPose` 확정 규칙과 같다 (`logic.test.js`에서 확인). 화면 버튼 모드(웹캠 꺼짐)에서는 손 인식 소식이 오지 않아 뜨지 않는다.

## 입력 확정 기준 (지금 값)

- `ctx.hand.waitForPose({ holdMs, since: 문제 제시 시각, names: HANDS })`로 받는다
- 가위(`V`)·바위(`ROCK`)·보(`PAPER`) 중 하나를 **1초**(속도 "천천히"면 1.5초) 유지하면 확정
- 문제가 나오기 전부터 들고 있던 손은 인정하지 않는다 (공통 규칙, `docs/hand-api.md`)
- 손 인식이 어려울 때를 위해 화면 버튼으로도 답할 수 있다 (`Promise.race`로 먼저 들어온 입력 사용)

## 기록 (`ctx.log.record`)

회차(5문제)가 끝날 때 한 번 기록한다. 중간에 화면을 나가면 기록하지 않는다.

- `total`: 문제 수, `done`: 조건에 맞게 낸 문제 수(한 번에 + 다시 해서), `skipped`: 건너뛴 수
- `avgReactionMs`: 문제가 나온 뒤 **첫 답**까지 걸린 시간의 평균 (건너뛴 문제 제외, 없으면 `null`)
- `detail: { difficulty, speed, questions: [{ robotHand, condition, status, answers: [{ hand, via, outcome, reactionMs }] }] }`
  - `status`: `first`(한 번에) | `second`(다시 해서) | `shown`(답을 함께 확인) | `skipped`(건너뜀)
  - `via`: `hand`(손 인식) | `button`(화면 버튼)
- 사용자 이름 등 개인정보는 기록하지 않는다

## 동시에 가위바위보 (2026-11-18 D 결정)

홈 **"하나만 해 보기"**로 들어왔을 때만(`ctx.single === true`) 첫 화면에서 고를 수 있다. 코스(오늘의 활동)에서는 위 사고력 모드만 나온다.
진짜 가위바위보처럼 **"보!"에 맞춰 로봇과 동시에** 손을 낸다. 승패는 운이고, "보!"에 맞춰 제때 냈는지를 기록한다.

| 항목 | 정한 값 |
|---|---|
| 한 회차 | 5판 (`QUICK_GAMES`) |
| 진행 | "가위"→"바위"→"보!"(사고력 모드와 같은 간격). "보!" 순간 `showPose`를 보내고 기다리지 않는다 (사용자와 동시에) |
| 손 입력 | "가위"부터 받는다. 손 인식(`waitForPose`, `since` = "보!" 0.3초 전) 또는 화면 버튼(누른 순간) 중 먼저 온 것 |
| 확정 시간 | 0.3초 유지 (천천히 0.5초) — 사고력 모드(1초)보다 짧다 (`quickTiming`) |
| 제때 (`timingOf`) | "보!" 0.3초 전(`EARLY_MS`) ~ "보!" 뒤 쉬움 1.5초 / 보통 1초 / 어려움 0.7초 (천천히 +0.5초) |
| 결과 | 제때: 이김·비김·짐 / 너무 먼저·늦게: 승패 없이 "조금 빨랐어요/늦었어요. '보!' 소리에 맞춰 내 볼까요?" / 손 없음: 다음 판 안내 |
| 로봇 반응 | 사용자가 이기면 `react('ok')`. 판 사이에 `rest()` |
| 요약 화면 | 판별 한 줄 + "'보!'에 맞춰 낸 판 n번 · 이김·비김·로봇이 이김 수". 점수·능력 평가처럼 보이지 않게 |

- 손 인식 주의: "가위, 바위" 동안 주먹을 흔들고 있으면 그 주먹은 "보!" 전부터 든 손이라 **너무 먼저**가 된다. 안내 화면에서 "손을 카메라 밖으로 내리고 기다려 주세요"라고 알려 준다. 실물(웹캠)에서 확인 필요.
- 늦게 내면 로봇 손을 보고 낼 수 있으므로 승패를 따지지 않는다.

기록: `program: 'step2-rps'`, `total`: 판 수, `done`: 제때 낸 판 수, `skipped`: 손이 안 보인 판 수,
`avgReactionMs`: 제때 낸 판에서 "보!"부터 손을 만들 때까지 평균 (먼저 낸 것은 0으로).
`detail: { mode: 'quick', difficulty, speed, lateMs, wins, draws, losses, games: [{ robotHand, hand, via, timing, timingMs, outcome }] }`
— `timing`: `ontime` | `early` | `late` | `none`. 사고력 모드 기록에는 `detail.mode`가 없다.

## 하지 말아야 할 것

- `src/core/`를 import 하거나 고치지 않는다. **`ctx`만 사용한다.**
- `logic.js`에서 DOM이나 `ctx`를 쓰지 않는다 (테스트할 수 있게 순수 함수로 유지).
- "틀렸습니다", "실패" 대신 "다시 해 볼까요?"를 쓴다.
- 결과를 점수·능력 평가처럼 보이게 표시하지 않는다.
