# 도전 활동: 공 주고받기 (challenge-ball)

- **담당:** A (B가 처음 만들고(#162, #163), 2026-11-26부터 A가 이어서 만든다)
- 이 폴더 밖 파일은 고치지 않는다. 필요하면 이유를 설명하고 확인받는다
- 기본 활동 **손운동(STEP 4)의 짝**. 홈의 손운동 카드 아래 "도전" 칸에서 연다 (`dashboard/catalog.js` `CHALLENGES`, #132). **코스에는 들어가지 않는다**

## 목적

화면이 알려 주는 손으로 공을 로봇에게 **건네고**, 로봇이 펴 주는 공을 알려 준 손으로 **돌려받는** 활동.
단계가 오를수록 손 지시가 바뀌고 섞여서, 지시를 보고 기억하며 양손을 번갈아 쓴다.
교육·체험용 활동이며, 치료·예방 효과를 주장하지 않는다.

- 공: AIHand 구성품 40mm 공 **1개** (색은 상관없음)
- **받기는 손 인식**(웹캠): 펼친 손이 보이면 로봇이 공을 내려놓는다 (2026-11-26 A). 그 밖의 입력은 화면 버튼
- 어느 손을 썼는지(왼손·오른손), 공이 잡혔는지는 확인하지 않는다 (사용자를 믿는다)
- 색 인식·색 이름 부탁은 넣지 않기로 했다 (11/26 B 결정. WonderCam 색 모드는 펌웨어 변경이 필요해서 A 확인 사항)

## 단계

**2026-11-27 A (실물 테스트): 한 가지로만 한다.** 단계 차이가 잘 느껴지지 않아 시작 화면의 단계 고르기를 뺐다. 언제나 아래 1단계(`PLAY_LEVEL`)로 하고, `ctx.settings.challengeLevel`은 쓰지 않는다. 대시보드도 이 활동은 사람별 시작 단계·"N단계" 표시에서 뺀다 (`catalog.js` `singleLevel: true`). 기록의 `detail.level`은 1로 남는다. 2·3단계 값(`LEVELS`)은 다시 쓸 수 있게 `logic.js`에 남겨 두었다 (예전 설명):

| 단계 | 손 지시 | 지시 보이기 |
|---|---|---|
| 1단계 | 편한 한 손으로 건네고 같은 손으로 받기. 손을 고르지 않는다 (2026-11-27 A: 손 고르기 화면을 뺌, 확인도 안 하므로) | 계속 보임 |
| 2단계 | 건네는 손과 받는 손이 다름, 번마다 번갈아 (오른→왼, 왼→오른, …) | 계속 보임 |
| 3단계 | 4가지(오른→오른, 오른→왼, 왼→왼, 왼→오른) 중 무작위, **바로 앞과 같은 지시는 이어 나오지 않음** | 5초(느리게 8초) 뒤 또는 [준비됐어요]를 누르면 가려짐. 시간이 지나 가려져도 [준비됐어요]를 눌러야 넘어감. [다시 보기]로 다시 볼 수 있음 |

- 한 회차 **4번** 주고받기 (`EXCHANGES`, 11/26 B 결정: 6번에서 줄임). 로봇이 공을 쥐는 횟수라서 **10번 이하**로 둔다 (11/23 약지 문제)
- (예전) 미리 고른 단계: `ctx.settings.challengeLevel`. 지금은 쓰지 않는다
- `ctx.settings.difficulty`(기본 활동용)는 쓰지 않는다. 속도 느리게(`SLOW`)는 "셋, 둘, 하나" 박자·가리기·받기 확정 시간·받을 손을 기다리는 시간만 늘린다

## 흐름 (한 번 주고받기)

1. 손 지시 보기: "건네는 손 → 받는 손" 칸 + "오른손으로 건네고, 왼손으로 받아요" → [준비됐어요]
2. 건네기: 로봇 `showPose('PAPER')` → "셋, 둘, 하나" ([공을 댔어요]를 누르면 바로) → `showPose('ROCK')`
   - 공은 로봇 **엄지와 검지 사이**에 대고, 다 쥘 때까지 떼지 않는다 (2026-11-27 실물 테스트: 그쪽에 대야 잘 잡음)
3. 받기: "손을 펴서 받쳐 주세요" → 아래 셋 중 먼저 오는 것으로 `showPose('PAPER')` (`waitReceive`)
   - 웹캠에 **받기 모양**(`RECEIVE_POSES`: `PAPER`, `FOUR`)이 확정됨: 이 단계가 시작된 뒤에 편 손을 0.5초(느리게 0.8초) 유지 (`receiveHoldMs`, 공통 `waitForPose`) → **바로 놓지 않고** "이제 그 손을 로봇 손 바로 아래로 옮겨 주세요" + "셋, 둘, 하나" 뒤 놓는다 (2026-11-27 실물 테스트: 웹캠에 손을 보이는 자리와 공이 떨어지는 자리가 달라 공이 바닥에 떨어짐)
   - [손을 받쳤어요] 버튼
   - 10초(느리게 15초, `receiveWaitMs`) 안에 둘 다 없으면 "손을 받쳐 주세요. 로봇이 곧 공을 내려놓아요" → "셋, 둘, 하나" 뒤 편다 (공을 오래 쥐지 않게)
   - 기다리는 동안 안내 줄: 손이 안 보임 / 손가락을 모두 펴 주세요 / 손을 잠깐 내렸다가 다시 펴 주세요(이 단계 전부터 펴고 있던 손) / 손이 보여요
4. 받은 뒤: [다음으로]·[다시 건네기](공이 떨어졌을 때, 같은 지시로 다시)·[그만하기]. **저절로 넘어가지 않는다** (공을 줍는 동안 넘어가지 않게)
5. 4번 끝: `react('ok')` → `rest()` → 기록 → 끝 화면 ("한 번 더 하기")

로봇이 공을 쥐고 있는 시간: 쥔 뒤부터 받기 모양이 확정되거나 버튼을 누를 때까지(길어도 10초, 느리게 15초) + 웹캠·시간 초과면 "셋, 둘, 하나" 3초(느리게 4.5초).

**받기 모양 [검증 필요]**: 웹캠은 로봇 받침대 앞에서 사람 쪽을 보므로, 손바닥을 위로 받친 손은 손가락이 웹캠 쪽으로 누워 겹쳐 보인다. 판정(`core/hand/fingers.js`)은 3D 거리 비율이라 방향은 덜 타지만, 랜드마크가 흔들리면 `PAPER` 대신 `FOUR`나 다른 모양이 나올 수 있다. 그래서 `FOUR`도 받기로 치고 화면 버튼을 함께 둔다. 실물 확인은 `docs/hardware-check.md` 6번

회차 시작에 `hello()`.

## 공 따라가기 (2026-11-27 A, 펌웨어 F5)

- 건네기에서 로봇이 손을 편(`PAPER`) 뒤 `ctx.robot.followBall(true)` → 손목이 공을 따라 돈다 (WonderCam 색 인식, 카메라가 손목과 함께 돎. 공식 예제 6.13 Color Tracking)
- 켜지면 "공을 로봇 손 가까이 가져와 주세요. 가까이 오면 로봇이 잡아요" → **공이 손 가까이 오면 바로 쥔다** (펌웨어가 화면 속 공 크기로 판단해 따라가기를 멈추고 `BALL,NEAR` → `followBall`의 `onNear`). [공을 댔어요]도 바로 쥔다. `followMs`(10초, 느리게 15초) 안에 둘 다 없으면 "셋, 둘, 하나" 뒤 쥔다. 쥐기 전에 `followBall(false)` (손목은 그 자리)
- 가까이 판단 (펌웨어): (1) 공이 가운데에서 크게(`BALL_NEAR_AREA` 12000) 0.3초, 또는 (2) 가운데에서 꽤 크게(`BALL_CLOSE_AREA` 5000) 보이다가 0.4초 넘게 사라짐. 공을 손 바로 앞에 대면 WonderCam에서 공이 사라지기 때문 (2026-11-27 실물). 기준 크기는 펌웨어 `DEBUG_BALL`로 재서 정한다 [검증 필요]
- Mock·펌웨어 F4 이하·카메라 문제면 `false` → 지금처럼 바로 "셋, 둘, 하나"
- 공 색: **초록 또는 파랑**, WonderCam **Color ID 1**에 학습 (`firmware/README.md` "F5 공 따라가기")
- 손목 안전 범위 60°~120° (펌웨어). 끝날 때 `rest()`가 90°로 돌린다
- 화면을 떠나면(unmount) `followBall(false)`

## 꼭 지킬 것 (로봇과 공)

- **공을 쥔 동안(`s.holding`)에는 `showPose('PAPER')` 말고 다른 로봇 명령을 보내지 않는다** (`react`·`hello`·`rest`·다른 손모양은 공이 떨어진다). 칭찬은 공을 돌려준 뒤에
- **끝날 때는 언제나 공을 먼저 돌려준다**
  - [그만하기]를 공을 쥔 동안 누르면: "공을 먼저 돌려 드릴게요. 손을 받쳐 주세요" → "셋, 둘, 하나" → `PAPER` → `rest()` (`giveBack`)
  - 받을 손을 기다리는 동안 누르면: 위와 같이 안내 → "셋, 둘, 하나" → `PAPER`
  - 손이 안 보여 내려놓는 "셋, 둘, 하나" 중에 누르면: 손을 편 뒤 끝낸다
  - 화면을 떠나면(`unmount`): 공을 쥐고 있으면 바로 `PAPER` (공이 떨어질 수 있어도 서보 보호가 먼저)
- `s.holding`은 `ROCK` 명령을 **보내기 전에** 켠다 (그사이 화면을 떠나도 손을 펴게)
- 로봇 `DONE`은 시간이 지나면 오는 응답이다. 공이 정말 잡혔는지는 모른다 (`docs/hardware-check.md`)

## 버튼 입력

- 화면을 넘기는 버튼은 두 번 눌러도 처음 하나만 받는다 (`firstOnly`). [다시 보기]는 화면을 넘기지 않으므로 여러 번 눌러도 된다 (`repeat: true`)
- 로봇이 움직이는 동안 누른 버튼은 줄 서 있다가 다음 기다리기에서 바로 받는다 (`sender`·`s.queued`). 새 화면을 그리면 버리되, [그만하기]는 남겨 둔다
- 손 인식(웹캠)은 받기에서만 쓴다 (`ctx.hand.waitForPose`, 기다리는 동안 `ctx.hand.onPose`로 안내). 확정 규칙을 따로 만들지 않는다. WonderCam(`ctx.card`)은 쓰지 않는다
- **내 손 캠 화면** (2026-11-27): 받을 차례(`active: 'receive'`) 화면에만 오른쪽에 거울 웹캠 영상 + "지금 손" 글자. 공통 부품 `src/ui/cam-box.js`, unmount 때 `screen.close()`
- `unmount()`에서 손 입력 기다리기(`s.waits`)를 모두 abort 한다

## 기록 (`ctx.log.record`)

회차가 끝날 때 한 번. **끝까지 하지 않은 회차(그만하기, 화면을 떠남)는 기록하지 않는다.**

- 공통 필드: `total` 4(주고받기로 한 횟수), `done` 끝까지 주고받은 횟수, `skipped` 0, `avgReactionMs` `null` (맞고 틀림이나 반응 시간을 재지 않음)
- `detail: { level, speed, hand, exchanges }`
  - `hand`: 언제나 `null` (11/27까지의 1단계 기록에는 고른 손 `'right'|'left'`가 있을 수 있다)
  - `exchanges`: `{ give, receive, retries, replays }` (손은 지시 기준 `'right'|'left'`, 1단계는 `'any'`(편한 손)·`'same'`(같은 손). `retries` 다시 건네기 수, `replays` 다시 보기 수)
- 화면에 점수·등급처럼 보이는 표현을 쓰지 않는다 ("공을 4번 주고받았어요")
